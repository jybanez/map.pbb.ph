## Storage and failure behavior

Version1 database `pbb-personal-layers-v1`, store `documents`, holds one schema1 document with a revision and named layers containing stable IDs, visibility and validated GeoJSON. This database is separate from disposable map-resource metadata/responses; map-cache pruning does not delete authored layers. Read validation rejects unsupported schemas, malformed layer metadata and strict invalid geometry without replacing saved data. Writes atomically compare revisions and commit the new document; stale-tab conflicts reject instead of merging or overwriting. Geometry callbacks defer snapshots/persistence outside adapter events. Multiple changes serialize with the latest document/revision.

No account transport, location/sensor persistence or automatic trail exists. Denied/quota/corrupt/conflicting storage produces visible feedback. Failed geometry writes keep the in-memory document, stop further automatic writes, and offer an explicit JSON backup action; beforeunload warns when committed work is unsaved or saving. Failed form saves keep entered values and the form open. A backup contains the current recoverable geometry; no import UI is supplied. Browser origin clearing/eviction can still remove local data, so this is not an indefinite-storage guarantee.
