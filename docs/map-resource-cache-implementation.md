## Runtime contract

`assets/map-resource-cache.js` routes the configured server's vector, POI, terrain and glyph paths, plus explicitly configured sprite URLs. URL normalization handles glyph spaces while preserving query parameters. Keys include the exact configured server, dataset generation and canonical URL. Binary/image requests return independent ArrayBuffers; sprite JSON returns parsed JSON. Image admission decodes with createImageBitmap before persistence, checks bounded positive dimensions and closes the temporary image; MapLibre subsequently performs its own rendering decode. The current style has no sprites; future approved sprite JSON/PNG/retina URLs belong in `config.spriteUrls`.

Readable HTTP 200 GET responses with appropriate MIME are admitted. Redirects, opaque responses, HTML/error content, unexpected origins and resources over 4 MiB are rejected. Bodies are bounded while streaming, and transport has a 15-second deadline. Private/no-store responses may display but are not saved. Successful public MapServer GETs were independently checked: vector protobuf, terrain PNG, POI protobuf and glyph protobuf; CORS was readable in Chromium. The observed server policy is public caching with a one-day max-age. Existing attribution is retained.

A hit displays immediately. Seven-day age triggers an asynchronous request-driven refresh; age never removes a tile. Offline/failed refresh and unsuccessful replacement retain the old bytes. Shared misses have independent consumers: cancelling one does not cancel another; cancelling all aborts transport. Teardown aborts consumers/refreshes and removes the protocol, without deleting device data. UI callbacks cannot break cache/transport recovery.

`assets/map-cache-store.js` writes a new immutable response key before committing the metadata pointer. Only after commit is the previous response removed. Metadata and maintenance serialize through Web Locks and an IndexedDB lease, also available without Web Locks. Reconciliation removes missing pointers and orphaned responses under that same serialization. The low-level storage queue retains its 32-operation cap. Resource transport now uses eight slots held until each optional write settles, so ordinary tile bursts backpressure before fetching instead of overflowing that queue. Validated bytes display before persistence finishes. At most eight resource bodies (each at most 4 MiB before decoding/copies) await storage; queued transports hold URLs/controllers only, with a 1,024-request backlog cap and cancellation before fetch. Direct low-level queue saturation, cancellation, quota/budget admission and eviction still limit coverage. Reads/touch operations do not delay network display.

Resource budget is 100 MiB or 20% of the reported origin quota, whichever is smaller, with 4,000 indexed responses. LRU pruning does not use age as expiration and protects the response being replaced. A quota failure prunes/retries once, then disables further writes for that controller context. Denied/unavailable storage falls back to online transport quietly. Storage estimates are approximate; browser eviction and external data removal still apply.

Dataset snapshots contain only the built public map style/server generation. If a requested startup base tile proves a new generation unavailable, the loader chooses one saved prior generation and its complete style rather than mixing individual old/new tiles. Servers are isolated. These snapshots do not contain GPS, sensor values, a trail or camera history. Tile URLs themselves reveal requested geographic areas and remain origin-local device data.

## Shell and presentation

`scripts/map-shell-graph.json` declares explicit PBB Map entry assets and 18 used Helper component roots. `scripts/build-shell-manifest.mjs` resolves their registry dependencies and recursive module/CSS/URL dependencies, rejecting missing paths or undeclared application component names. The canonical loader uses bundle preference by default and explicitly on all application/lazy calls; selected bundle or factory errors propagate without modular retry. The builder validates every used component/dependency against pinned bundle modules/exports, and includes only Helper loader/main JS/main CSS. No narrow Helper capability was needed: the existing canonical loader already provides this behavior for the covered ui prefix. No game, inspection or new drawing/icon runtime is adopted. MapLibre embeds its worker and the person renderer embeds its mesh; the WMM coefficients/model follow static imports. Run the build after any deployed runtime edit, or `node scripts/build-shell-manifest.mjs --check` to detect a stale manifest. The worker is registered at a stable URL with cache-independent update checks. A partial or hash-mismatched install never activates.

Runtime text uses LF enforced by `.gitattributes`, so shell bytes remain reproducible across Windows/Linux checkouts. The byte inventory was refreshed after newline-only normalization. The scientific geomagnetism runtime is exempt from conversion and keeps its independent pinned original checksums. No numerical/model code was changed.

The worker caches only this graph. It never saves MapServer responses, Account calls or sensors. Navigation returns cached HTML directly. Existing clients retain their bound shell graph through worker takeover until navigation/reload; old shell caches are retained for safety. Owner9397/task205 supersedes manual update actions and announcements: installation verifies every file, then automatically calls skipWaiting. Activation preserves existing client bindings and claims clients without any page reload; new navigations bind to the newest complete graph. There is no Update Map control, update toast, replacement prompt or multi-tab activation refusal. Bindings are retained rather than pruned against a potentially stale matchAll snapshot, so concurrent navigation cannot lose its generation binding. Retained old shells consume separate origin storage and can eventually constrain new installs; automatic deletion of graphs still needed by clients is deliberately avoided.

`map.webmanifest` references the original local icon and native browser install affordances. There is no installation prompt. Caching requires secure origin APIs; opening as an installed PWA does not create additional geographic coverage.

The optional Helper signal component uses the five accepted `0.21.285` runtime artifacts from merged Helper revision `62b019895917d1d8e67fe3fa864763ec97473e8b`, verified against its LF-normalized checksums. It shows bars only immediately before the compass: neutral unknown, four bars for an observed successful MapServer request, zero bars for observed failure. This is reachability, not Wi-Fi measurement or a speed grade, and does not control the cache. Only actually missing requested detail produces one canonical accessible warning. Online/visibility hints and bounded retries recover pending resources; availability does not gate saved mapping. Slow tile loading keeps an already-created map and its controls usable.
